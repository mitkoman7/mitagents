Pydantic in Self-Evolving Agent

How dynamic schema validation enables LangChain tool evolution

📦 What is Pydantic?

Pydantic is a Python library for data validation using Python type annotations. It ensures that data conforms to expected types and structures, automatically converting and validating input data. 

from pydantic import BaseModel

class User(BaseModel):
    name: str
    age: int
    email: str

# Pydantic validates and converts data automatically
user = User(name="Alice", age="25", email="alice@example.com")
# age is automatically converted from "25" (string) to 25 (int)
print(user.age)  # Output: 25 (as integer)

Key Features

  • Type Validation: Ensures data matches expected types
  • Automatic Conversion: Converts compatible types (e.g., "25" to 25)
  • Default Values: Supports optional fields with defaults
  • Schema Generation: Auto-generates JSON Schema from models
  • Error Messages: Clear validation error messages

🔗 Why LangChain Needs Pydantic

LangChain uses Pydantic models to define tool schemas. When an AI agent calls a tool, LangChain needs to know what arguments the tool expects and their types.

# LangChain tool with Pydantic schema
from langchain.tools import StructuredTool
from pydantic.v1 import BaseModel, Field

class CreateNotebookArgs(BaseModel):
    """Arguments for creating a notebook"""
    path: str = Field(description="Workspace path for notebook")
    language: str = Field(default="PYTHON", description="Language")

tool = StructuredTool.from_function(
    func=create_notebook,
    name="workspace_import",
    args_schema=CreateNotebookArgs  # ← Pydantic tells LangChain the args
)

⚠️ The Pydantic Version Problem

The Error We Encountered

ValidationError: 1 validation error for StructuredTool
args_schema
  subclass of BaseModel expected (type=type_error.subclass; expected_class=BaseModel)

Pydantic has two major versions with incompatible APIs:

Feature Pydantic v1 Pydantic v2
Import from pydantic import BaseModel from pydantic import BaseModel
Compatibility Layer N/A (native) from pydantic.v1 import BaseModel
LangChain Uses ✓ Yes (internally) ✗ Not directly
Default in Python 3.9+ No ✓ Yes

The Solution

LangChain internally uses Pydantic v1 compatibility layer. We must import from pydantic.v1 to create compatible models!

🔧 Dynamic Pydantic Model Creation

In our self-evolving agent, we don't know tool schemas at compile time - they're discovered at runtime. We use create_model() to dynamically generate Pydantic models from JSON schemas.

The Transformation Function

from typing import Optional
from pydantic.v1 import BaseModel as BaseModelV1, Field as FieldV1, create_model as create_model_v1

def create_pydantic_model_from_schema(tool_name: str, input_schema: dict) -> type:
    """Create a Pydantic v1 model dynamically from inputSchema"""
    properties = input_schema.get("properties", {})
    required = set(input_schema.get("required", []))

    field_definitions = {}

    for prop_name, prop_def in properties.items():
        prop_type = prop_def.get("type", "string")
        description = prop_def.get("description", "")
        default = prop_def.get("default", None)

        # Map JSON schema types to Python types
        type_mapping = {
            "string": str,
            "integer": int,
            "number": float,
            "boolean": bool,
            "array": list,
            "object": dict
        }
        python_type = type_mapping.get(prop_type, str)

        # Required fields have no default; optional fields use Optional[]
        if prop_name in required:
            field_definitions[prop_name] = (python_type, FieldV1(description=description))
        else:
            field_definitions[prop_name] = (Optional[python_type], FieldV1(default=default, description=description))

    # Create dynamic model with v1 base class
    model_name = f"{tool_name.title().replace('_', '')}Args"
    return create_model_v1(model_name, __base__=BaseModelV1, **field_definitions)

Output: Dynamic Pydantic Model

# This is equivalent to writing:
class WorkspaceImportArgs(BaseModelV1):
    path: str = FieldV1(description="Workspace path for the notebook")
    content: str = FieldV1(description="Notebook content")
    language: Optional[str] = FieldV1(default="PYTHON", description="Language")
    format: Optional[str] = FieldV1(default="SOURCE", description="Format")
    overwrite: Optional[bool] = FieldV1(default=False, description="Overwrite existing")

💡 Why This Architecture Matters

Without Pydantic Schema With Pydantic Schema
AI doesn't know required arguments AI knows exactly what arguments to provide
Arguments may be missing or wrong type Arguments validated before function call
Errors happen at execution time Errors caught during argument parsing
path="" (empty string passed) path="/Users/user/notebook" (correct value)

The Key Insight

Pydantic acts as the contract between the AI model and the tool function. It tells the AI "here's what I need" and validates "here's what you gave me" - ensuring reliable tool execution in a self-evolving system where tools are discovered at runtime.
